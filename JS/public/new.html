1. What Exactly Is a Class?

A class is a reusable definition for creating objects with related properties and methods. Think of it as a blueprint that defines the structure and behavior of a particular kind of object.

Imagine we are building an application that manages users. Every user has a name and an age, and every user should be able to greet someone. 

class User {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }

    greet() {
        console.log(`Hello, ${this.name}`);
    }
}

const user1 = new User("k7", 10);
const user2 = new User("raja", 78);

console.log(user1);
user1.greet();

user2.greet();
console.log(user2.age);
Output
User { name: 'k7', age: 10 }
Hello, k7
Hello, raja
78
Understand the Structure
Code What It Means
class User Defines the structure and behavior of User objects.
constructor(name, age) Receives the initial values when a new User instance is created.
this.name = name Stores the received name on the current instance.
greet() Defines an action that User instances can perform.
new User("k7", 10) Creates a new User instance and runs its constructor.
user1 and user2 Refer to two different instances, each with its own name and age.

The class provides a common definition, but each call to new User(...) creates a separate instance with its own data.

One Important Detail

Although both objects can use greet(), their name and age values are separate. With JavaScript classes, ordinary instance methods such as greet() are defined on the class's prototype rather than being recreated as separate own methods on every instance.

2. What Exactly Is constructor()?

A constructor is a special method inside a JavaScript class that initializes a new instance. It commonly receives initial values through parameters and assigns those values to the new object's properties.

Look at this part of our User class:

constructor(name, age) {
    this.name = name;
    this.age = age;
}

There are two important things happening here:

  • name and age are parameters that receive values.
  • this.name = name and this.age = age assign those values to properties of the current instance.

Important: The constructor does not automatically copy parameter values into properties. The assignments inside the constructor do that.

Example: Creating a User
class User {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }
}

const user1 = new User("Arun", 25);

User { name: 'Arun', age: 25 }

Each call to new User(...) creates a separate instance and runs the constructor for that instance. Each instance receives its own property values.

3. Is constructor() Mandatory?

No! A constructor is optional in a JavaScript class. If you don't write one, JavaScript provides a default constructor.

Example 1: A Class Without a Constructor
class User {
}

const user1 = new User("Arun");

console.log(user1);      // User {}
console.log(user1.name); // undefined

The object is created successfully, even though the class has no explicit constructor.

But notice something important: we passed "Arun", yet user1 does not have a name property.

Why?

JavaScript does not automatically store arguments as object properties. The default constructor does not assign "Arun" to user1.name.

new User("Arun")
|
New instance created
|
No code assigns a name property
|
user1.name === undefined
Example 2: Assigning a Property After Creating the Object

We can create the object first and assign its properties afterward.

class User {
}

const user1 = new User();

user1.name = "Arun";

console.log(user1.name); // Arun

This works because we explicitly assign "Arun" to the object's name property.

We don't need a constructor just to create an object or add properties later.

Example 3: Using Class Fields Without a Constructor

Sometimes, we want every instance to start with the same default values. We can define those values directly as class fields. 

class User {
    role = "member";

    greet() {
        console.log("Hello!");
    }
}

const user1 = new User();
const user2 = new User();

console.log(user1.role); // member
console.log(user2.role); // member

user1.greet(); // Hello!

Here, an explicit constructor isn't necessary because:

  • role = "member" initializes the role property on each new instance.
  • greet() defines a method that instances can use.
  • No constructor parameters or additional initialization logic are needed.
Example 4: When Do We Need a Constructor?

Suppose each user needs a different name and age when created. A constructor is a convenient way to initialize those values. 

class User {
    constructor(name, age) {
        this.name = name;
        this.age = age;
    }
}

const user1 = new User("Arun", 25);
const user2 = new User("Priya", 28);

console.log(user1.name); // Arun
console.log(user2.name); // Priya

In this example, the constructor receives different arguments for each instance and assigns them to the appropriate properties.

Built-in JavaScript Constructors

JavaScript provides built-in constructors that we can use with the new keyword to create objects. One useful example is Date, which represents a date and time.

1. new Date()

What Is Date?

Date is a built-in JavaScript constructor used to create objects that represent a specific point in time.

Let's start by getting the current date and time.

const now = new Date();

console.log(now);
console.log(now.getFullYear());
console.log(now.getMonth());
console.log(now.getDate());
What Happens Here?
  • new Date() creates a Date object representing the current time.
  • getFullYear() returns the year according to the computer's local time zone.
  • getMonth() returns the month as a number from 0 to 11.
  • getDate() returns the day of the month, from 1 to 31.

2. Create a Specific Date

You don't always need the current date. You can create a Date object for a particular date by passing values to the constructor. 

const birthday = new Date(2000, 0, 15);

console.log(birthday.getFullYear()); // 2000
console.log(birthday.getMonth());    // 0
console.log(birthday.getDate());     // 15

In this numeric constructor form, the arguments are:

Argument Meaning Value in This Example
First Year 2000
Second Month index (0–11) 0 = January
Third Day of the month 15

Therefore, new Date(2000, 0, 15) represents January 15, 2000, at midnight in the computer's local time zone.

Remember: The month argument in this numeric form is zero-based. Use 0 for January and 11 for December.

3. Does new Date() Get the Date from the Internet?

No. Calling new Date() does not search the internet for the current date and time. It uses the system clock available to the JavaScript environment.

  • If the computer's clock is incorrect, the reported current time may also be incorrect.
  • The Date object represents a point in time, while methods such as getHours() and getDate() interpret that time using the computer's local time zone.
  • Two computers in different time zones can show different local dates or clock times for the same instant.

Built-in JavaScript Constructor: new Map()

1. What Is a Map?

A Map is a JavaScript data structure that stores key-value pairs. Each key is associated with a value, and we can retrieve that value using its key.

Imagine maintaining a collection of employee IDs and names.

const employees = new Map();

employees.set(101, "Arun");
employees.set(102, "Priya");
employees.set(103, "Kumar");

console.log(employees);

console.log(employees.get(101)); // Arun
console.log(employees.get(102)); // Priya
console.log(employees.get(100)); // undefined

console.log(employees.size); // 3

get(101) Retrieves the value associated with key 101. "Arun"
get(100) Looks up a key that doesn't exist. undefined
size Returns the number of entries. 3
employees (Map)

101 → Arun

2. What Happens When the Same Key Is Used Again?

A Map cannot contain duplicate keys. If you use an existing key again with set(), its value is updated instead of creating another entry. 

const scores = new Map();

scores.set("Arun", 80);
scores.set("Priya", 90);
scores.set("Arun", 95);

console.log(scores.get("Arun")); // 95
console.log(scores.size);        // 2

The Map contains only two unique keys: "Arun" and "Priya".

When scores.set("Arun", 95) executes, Arun's existing value changes from 80 to 95. No additional entry is created, so the size remains 2.

தமிழில்: ஏற்கெனவே உள்ள "Arun" key-ஐ மீண்டும் பயன்படுத்தினால், பழைய value update ஆகும். அதே key-க்காக duplicate entry உருவாகாது.

2. What Is a Set?

You've learned that a Map stores key-value pairs. A Set is a JavaScript data structure that stores unique values. Adding the same value more than once does not create duplicate entries.

Imagine you have an array of numbers containing duplicates.

const numbers = [10, 20, 10, 30, 20, 40];

const uniqueNumbers = new Set(numbers);

console.log(uniqueNumbers);
// Set(4) { 10, 20, 30, 40 }

console.log(uniqueNumbers.size); // 4

  1. numbers contains six values, including duplicates.
  2. new Set(numbers) creates a Set using the array's values.
  3. Repeated values are stored only once.
  4. The resulting Set contains four unique values.

Important: The original array is not modified. The Set is a separate collection.

2. Adding and Removing Values

You can create an empty Set and add values individually using the add() method. 

const fruits = new Set();

fruits.add("Apple");
fruits.add("Banana");
fruits.add("Apple");

console.log(fruits);      // Set(2) { 'Apple', 'Banana' }
console.log(fruits.size); // 2

console.log(fruits.has("Apple")); // true

fruits.delete("Banana");

console.log(fruits.size); // 1

add("Banana") Apple, Banana 2
add("Apple") Apple, Banana 2
delete("Banana") Apple 1

Notice that adding "Apple" a second time does not increase the size. A Set keeps only one occurrence of that string value.

4. A Practical Example: Remove Duplicate Email Addresses

Suppose an API returns an array containing duplicate email addresses. We want to keep each email only once. 

const emails = [
    "arun@example.com",
    "priya@example.com",
    "arun@example.com"
];

const uniqueEmails = [...new Set(emails)];

console.log(uniqueEmails);
// ["arun@example.com", "priya@example.com"]

["arun@example.com", "priya@example.com", "arun@example.com"]

|

|

There are two important operations here:

  • new Set(emails) removes duplicate email values by storing only unique values.
  • [...new Set(emails)] uses spread syntax to collect the Set's values into a new array.
Remember: Spread syntax does not remove duplicates by itself. The Set removes duplicates; spread syntax converts the Set's iterable values into an array.

5. What If the Email Addresses Are Stored in an Object?

Sometimes, the data may be stored in an object rather than an array. 

const emails = {
    mail1: "arun@example.com",
    mail2: "priya@example.com",
    mail3: "arun@example.com"
};

const emailValues = Object.values(emails);

console.log(emailValues);
// ["arun@example.com", "priya@example.com", "arun@example.com"]

const uniqueEmails = [...new Set(emailValues)];

console.log(uniqueEmails);
// ["arun@example.com", "priya@example.com"]
Step-by-Step Explanation

Step 1: Extract the object's values.

const emailValues = Object.values(emails);

Object.values() returns an array containing the object's values, without the property names.

Step 2: Remove duplicates and create a new array.

const uniqueEmails = [...new Set(emailValues)];

Here, the Set removes duplicate email values, and the spread syntax creates an array from the Set.

6. Does Set Remove Duplicate Objects Too?

Be careful! For primitive values such as strings and numbers, Set recognizes equivalent values. But objects are compared by reference, not by their contents. 

const users = new Set();

users.add({ name: "Arun" });
users.add({ name: "Arun" });

console.log(users.size); // 2

Although both objects have the same properties and values, they are two separately created objects with different references. Therefore, both are stored in the Set.

However, adding the exact same object reference twice will not create a duplicate. 

const user = { name: "Arun" };

const users = new Set();

users.add(user);
users.add(user);

console.log(users.size); // 1

Map vs Set — The Main Difference

Both Map and Set store collections of values, but they serve different purposes.

Map
Key → Value
1 → Arun
2 → Priya
3 → Priya

Stores key-value pairs.

Keys must be unique, but values can repeat.

Set
Unique Values
Arun
Priya

Stores unique values only.

Adding the same value again does not create another entry.

1. Map — Keys Must Be Unique, Values Can Repeat

const users = new Map();

users.set(1, "Arun");
users.set(2, "Priya");
users.set(3, "Priya");

console.log(users.size); // 3
console.log(users.get(2)); // Priya
console.log(users.get(3)); // Priya

Why are there 3 entries?

The keys 1, 2, and 3 are different. Even though two entries have the same value, "Priya", both entries are stored because their keys are different.

Map
┌─────────┬─────────┐
│ Key │ Value │
├─────────┼─────────┤
│ 1 │ Arun │
│ 2 │ Priya │
│ 3 │ Priya │
└─────────┴─────────┘
size = 3
What If We Use the Same Key Again?
users.set(2, "Kumar");

console.log(users.size);    // 3
console.log(users.get(2)); // Kumar

The existing value for key 2 is updated from "Priya" to "Kumar". No new entry is created, so the size remains 3.

2. Set — Only Unique Values Are Stored

const users = new Set();

users.add("Arun");
users.add("Priya");
users.add("Priya");

console.log(users.size); // 2

console.log(users.has("Arun"));  // true
console.log(users.has("Priya")); // true

Why are there only 2 values?

The second add("Priya") does not add another entry because that value already exists in the Set.

Set
┌─────────┐
│ Value │
├─────────┤
│ Arun │
│ Priya │
└─────────┘
size = 2

JavaScript Wrapper Objects, Dictionary and Map

1. Why Should We Avoid new String(), new Number() and new Boolean()?

JavaScript has primitive values such as strings, numbers and booleans. It also provides built-in constructors that can create wrapper objects around these values.

The important difference is that using a constructor with new creates an object, whereas calling the corresponding function without new converts a value to a primitive.

Example 1: String
const a = "hello";
const b = new String("hello");

console.log(typeof a); // "string"
console.log(typeof b); // "object"

console.log(a === b);  // false

Although both appear to represent the text "hello", they are different types of values:

a = "hello"
Primitive string

b = new String("hello")
String wrapper object

The strict equality operator === compares both type and value. A primitive string and a String object are different, so the comparison returns false.

Example 2: Number
const a = 10;
const b = new Number(10);

console.log(typeof a); // "number"
console.log(typeof b); // "object"

console.log(a === b);  // false

10 is a primitive number, while new Number(10) creates a Number wrapper object.

Example 3: The Surprising Boolean Case
const a = false;
const b = new Boolean(false);

console.log(typeof a); // "boolean"
console.log(typeof b); // "object"

console.log(Boolean(a)); // false
console.log(Boolean(b)); // true

if (b) {
    console.log("This condition runs!");
}

Why does new Boolean(false) behave as true in a condition?

Because new Boolean(false) creates an object. In JavaScript, every ordinary object is truthy, even when the primitive value wrapped inside it is false, 0 or an empty string.

Important: Don't use if (new Boolean(false)) to check a boolean value. The condition will run because the wrapper object itself is truthy.

2. What Should We Use Instead?

When you need to convert a value into a string, number or boolean, call the built-in function without new. 

const name = String(123);
const age = Number("25");
const isActive = Boolean(1);

console.log(name);     // "123"
console.log(typeof name); // "string"

console.log(age);      // 25
console.log(typeof age); // "number"

console.log(isActive); // true
console.log(typeof isActive); // "boolean"
Expression Result Type
String(123) "123" Primitive string
Number("25") 25 Primitive number
Boolean(1) true Primitive boolean
new String("hello") Wrapper object "object"
new Number(10) Wrapper object "object"
new Boolean(false) Wrapper object "object"
When Would We Need Wrapper Objects?

In ordinary application code, almost never. You can call string methods on primitive strings without manually creating a String object. 

const name = "arun";

console.log(name.toUpperCase()); // "ARUN"

JavaScript allows many methods to be used on primitive strings, numbers and booleans through automatic boxing when needed. You normally don't need to create wrapper objects yourself.

Explicit wrapper objects are mainly useful when studying JavaScript's behavior or working with unusual legacy APIs that specifically require an object. They are not the normal way to represent strings, numbers or booleans.

Practical rule:

Use "hello", 10 and true for ordinary values.

Use String(value), Number(value) and Boolean(value) for conversions.

Avoid new String(), new Number() and new Boolean() in normal application code.

3. What Is a Dictionary?

A dictionary is a general programming concept: store a value under a key and retrieve it later using that key.

JavaScript doesn't have a separate built-in data type called Dictionary. An ordinary object or a built-in Map can be used as a dictionary. 

const userRoles = {
    101: "Admin",
    102: "Editor",
    103: "Viewer"
};

console.log(userRoles[101]); // "Admin"
console.log(userRoles[102]); // "Editor"

Here, the object is being used as a dictionary to map user IDs to roles.

தமிழில்: Dictionary என்பது தனியான JavaScript datatype கிடையாது. ஒரு key மூலம் value-ஐச் சேமித்து, அதே key மூலம் value-ஐப் பெறும் முறைக்குப் பெயர்தான் dictionary.

How Does an Object Work as a Dictionary?

When you write a numeric property name such as 101 in an ordinary object, JavaScript treats it as the string property key "101". 

const obj = {};

obj[101] = "Admin";

console.log(obj[101]);   // "Admin"
console.log(obj["101"]); // "Admin"

console.log(Object.keys(obj)); // ["101"]

Both obj[101] and obj["101"] access the same property because the number is converted to a string when used as an ordinary object property key.

4. What Is JavaScript's Built-in Map?

JavaScript provides a dedicated data structure called Map for storing key-value pairs. 

const userRoles = new Map();

userRoles.set(101, "Admin");
userRoles.set(102, "Editor");
userRoles.set(103, "Viewer");

console.log(userRoles.get(101)); // "Admin"
console.log(userRoles.get(102)); // "Editor"
console.log(userRoles.size);     // 3

A Map has its own methods for adding entries, retrieving values, checking keys and counting entries.

Object Dictionary vs Map
Feature Object as Dictionary Built-in Map
Stores key-value pairs Yes Yes
Key types Strings and symbols Any value, including objects and functions

Retrieve a value obj[key] map.get(key)

5. Why Doesn't Bracket Notation Work the Same Way on a Map?

This is the most important distinction to understand. A Map is still a JavaScript object, but its entries are stored in an internal Map collection, not as ordinary object properties.

Example A: An Ordinary Object
const obj = {};

obj[101] = "Admin";
obj[102] = "Admin2";

console.log(obj);
// { '101': 'Admin', '102': 'Admin2' }

console.log(obj[101]);   // "Admin"
console.log(obj["101"]); // "Admin"

With an ordinary object, bracket assignment creates or updates an object property.

Example B: Using Bracket Notation on a Map
const obj1 = new Map();

obj1[101] = "Adminttt";
obj1[102] = "Admin28t";

console.log(obj1[101]);   // "Adminttt"
console.log(obj1["101"]); // "Adminttt"

console.log(obj1.size);   // 0
console.log(obj1.get(101)); // undefined

Notice that obj1[101] returns "Adminttt". So why is the Map's size still zero?

Because this assignment:

obj1[101] = "Adminttt";

creates an ordinary property on the Map object. It does not add an entry to the Map's internal key-value collection.

obj1 = new Map()
|
+-- Ordinary object properties
| 101 → "Adminttt"
| 102 → "Admin28t"
|
+-- Map internal entries
(empty)

obj1.size = 0

The bracket properties are separate from the Map entries. That's why obj1[101] returns a string, but obj1.get(101) returns undefined.

The exact way a Map with extra ordinary properties is displayed by console.log() depends on the JavaScript environment. The reliable checks are size, get() and has().

The Correct Way to Store Entries in a Map
const obj1 = new Map();

obj1.set(101, "Adminttt");
obj1.set(102, "Admin28t");

console.log(obj1.get(101)); // "Adminttt"
console.log(obj1.get(102)); // "Admin28t"
console.log(obj1.size);     // 2

Now the values are stored as actual Map entries, so get() retrieves them and size counts them.

Remember:

obj[key] = value creates or updates an ordinary object property.

map.set(key, value) creates or updates an entry in a Map.

obj[key] reads an ordinary object property.

map.get(key) reads a value from the Map's internal collection.

தமிழில்:

  • obj[key] = value — ordinary object property-ஐ உருவாக்கும் அல்லது update செய்யும்.
  • map.set(key, value) — Map collection-ல் entry-ஐ உருவாக்கும் அல்லது update செய்யும்.
  • obj[key] — ordinary property-ஐப் படிக்கும்.
  • map.get(key) — Map collection-ல் உள்ள value-ஐப் பெறும்.

6. An Important Difference in Key Types

With an object, the keys 101 and "101" refer to the same property after key conversion. With a Map, the number and string are different keys. 

const obj = {};

obj[101] = "Admin";

console.log(obj[101]);   // "Admin"
console.log(obj["101"]); // "Admin"

const map = new Map();

map.set(101, "Admin");
map.set("101", "Editor");

console.log(map.get(101));   // "Admin"
console.log(map.get("101")); // "Editor"
console.log(map.size);       // 2

This is useful when a numeric ID and a text identifier must be treated as separate keys.

7. When Should You Use an Object or a Map?

Use an Object
  • Represent a user, product, configuration or other structured entity.
  • Store named properties such as user.name.
  • Build a simple dictionary with string or symbol keys.
const user = {
    name: "Arun",
    role: "Admin"
};

console.log(user.role); // Admin
Use a Map
  • Maintain a collection of key-value entries.
  • Use keys that can be objects, numbers or other value types.
  • Need convenient entry counting, insertion-order iteration and Map-specific methods. 
const roles = new Map();

roles.set(101, "Admin");
roles.set(102, "Editor");

console.log(roles.size); // 2

Map Methods in JavaScript

A JavaScript Map stores data as key-value pairs. It provides built-in methods to add entries, retrieve values, check whether keys exist, and remove entries.

1. Practical Example: Map Methods
const employees = new Map();

// 1. set() — add or update an entry
employees.set(101, "Arun");
employees.set(102, "Priya");

// 2. get() — retrieve a value
console.log(employees.get(101)); // "Arun"

// 3. has() — check whether a key exists
console.log(employees.has(102)); // true
console.log(employees.has(103)); // false

// 4. delete() — remove an entry
console.log(employees.delete(101)); // true

console.log(employees.has(101)); // false
console.log(employees.size);     // 1

// 5. clear() — remove all entries
employees.clear();

console.log(employees.size); // 0
2. Understand Each Method
Method / Property Purpose What It Returns
set(key, value) Adds an entry or updates the value of an existing key. The same Map, allowing method chaining.
get(key) Retrieves the value associated with a key. The stored value, or undefined if the key is absent.
has(key) Checks whether a key exists. true or false.
delete(key) Removes an entry. true if an entry was removed; otherwise false.
size Counts the Map's entries. A number.
clear() Removes every entry from the Map. undefined.

தமிழில்:

  • set() — value-ஐச் சேமிக்க அல்லது update செய்ய.
  • get() — value-ஐ எடுக்க.
  • has() — key இருக்கிறதா என்று பார்க்க.
  • delete() — குறிப்பிட்ட entry-ஐ நீக்க.
  • size — மொத்த entries எண்ணிக்கையைப் பெற.
  • clear() — எல்லா entries-ஐயும் நீக்க.
3. Important: set() Supports Method Chaining

The set() method returns the same Map, so you can call set() multiple times in one statement. 

const employees = new Map();

employees
    .set(101, "Arun")
    .set(102, "Priya")
    .set(103, "Kumar");

console.log(employees.size); // 3

Each call adds or updates an entry and returns the Map itself, allowing the next set() call.

Remember: set() returns the Map, but get() returns a stored value. These return values are different.
4. Important: What If a Key Doesn't Exist?
const employees = new Map();

employees.set(101, "Arun");

console.log(employees.get(999)); // undefined
console.log(employees.has(999)); // false
console.log(employees.delete(999)); // false

get() returning undefined means no value was found for that key, but it can also be the value explicitly stored for an existing key. Use has() when you need to distinguish those situations. 

const data = new Map();

data.set(1, undefined);

console.log(data.get(1)); // undefined
console.log(data.has(1)); // true

console.log(data.get(2)); // undefined
console.log(data.has(2)); // false

Both get(1) and get(2) return undefined, but only key 1 exists in the Map.

Object vs Map — How Do We Choose?

Both ordinary objects and Maps can store key-value data. The right choice depends on what you're representing and how you need to work with the data.

5. Use an Object for Structured Data

Use an object to describe an entity with named properties, such as a user profile, product, configuration or API record. 

const user = {
    name: "Arun",
    age: 25,
    role: "Admin"
};

console.log(user.name); // Arun
console.log(user.age);  // 25
console.log(user.role); // Admin

Here, name, age and role describe one user. The object represents a structured entity.

user (Object)
├── name → "Arun"
├── age → 25
└── role → "Admin"
6. Use a Map for a Key-Value Collection

Use a Map when you need a collection of entries that you look up by key, especially when keys may be numbers, objects or other non-string values. 

const employees = new Map();

employees.set(101, "Arun");
employees.set(102, "Priya");
employees.set(103, "Kumar");

console.log(employees.get(102)); // Priya
console.log(employees.size);     // 3
employees (Map)
├── 101 → "Arun"
├── 102 → "Priya"
└── 103 → "Kumar"

Here, the employee IDs are keys used to look up employee names. The collection has a built-in size property and methods such as set(), get(), has() and delete().
